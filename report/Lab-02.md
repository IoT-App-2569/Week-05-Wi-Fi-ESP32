## 7. คำถามท้ายการทดลอง (Post-Lab Questions)

1. เหตุใดการระบุ SSID ผิด (ข้อ 5.2.2) จึงส่งผลให้เกิด Disconnect Event ด้วย Reason Code `201` (`WIFI_REASON_NO_AP_FOUND`) ตั้งแต่เฟส Scan?

```
เพราะในขั้นตอนแรกสุดของการเชื่อมต่อ ESP32 จะต้องทำการสแกน หาเครือข่ายที่มีชื่อ SSID ตรงกับที่ตั้งค่าไว้ก่อน หากสแกนแล้วไม่พบชื่อ SSID นั้นอยู่ในอากาศเลย ESP32 จะหยุดกระบวนการทันทีและแจ้งเตือนว่าหา AP ไม่พบ โดยไม่จำเป็นต้องไปทำขั้นตอน Authentication หรือ Association
```

2. เหตุใดการพิมพ์ Password ผิด (ข้อ 5.2.3) จึงผ่านเฟส Auth และ Assoc มาได้ แต่มาล้มเหลวในเฟส 4-Way Handshake (Reason Code 15 หรือ 204)?

```
ในมาตรฐาน Wi-Fi แบบ WPA2/WPA3 การยืนยันตัวตน และการขอเข้าร่วม ในเฟสแรกๆ เป็นเพียงการแลกเปลี่ยนเฟรมพื้นฐานแบบ Open System ซึ่งจะสำเร็จเสมอ แต่ "รหัสผ่าน" จะถูกนำมาใช้จริงๆ ในเฟส 4-Way Handshake เพื่อคำนวณกุญแจเข้ารหัส เมื่อรหัสผ่านผิด การคำนวณกุญแจจึงไม่ตรงกับที่เร้าเตอร์ต้องการ ทำให้กระบวนการ Handshake ล้มเหลวและถูกตัดการเชื่อมต่อ
```

3. ลำดับการเกิด Event ระหว่าง WIFI_EVENT_STA_CONNECTED กับ IP_EVENT_STA_GOT_IP Event ใดเกิดขึ้นก่อนกัน และมีความหมายทางกายภาพของ Layer Network ต่างกันอย่างไร?

```
WIFI_EVENT_STA_CONNECTED เกิดขึ้นก่อน มีความหมายว่าการเชื่อมต่อในระดับ Link-Layer  หรือระดับคลื่นวิทยุสำเร็จแล้ว ส่วน IP_EVENT_STA_GOT_IP จะเกิดขึ้นตามมา มีความหมายว่าการเชื่อมต่อในระดับ Network-Layer สำเร็จแล้ว โดย ESP32 ได้รับการแจกหมายเลข IP จาก DHCP Server ของ Router ทำให้พร้อมรับส่งข้อมูลผ่านอินเทอร์เน็ตได้
```

4. สมาชิกตัวแปร reason ในโครงสร้าง wifi_event_sta_disconnected_t มีประโยชน์อย่างไรต่อการออกแบบระบบค้นหาสาเหตุและกู้คืนการเชื่อมต่อ (Auto-Reconnection Mechanism) ในแอปพลิเคชัน IoT?

```
มีประโยชน์อย่างมากในการระบุสาเหตุที่แท้จริงของการหลุดการเชื่อมต่อ เพื่อให้โปรแกรมสามารถจัดการข้อผิดพลาด ได้อย่างเหมาะสม เช่น หาก Reason แจ้งว่าหา AP ไม่พบ โปรแกรมอาจตั้งเวลาหน่วงนานขึ้นก่อนลองเชื่อมต่อใหม่ แต่หาก Reason แจ้งว่ารหัสผ่านผิด โปรแกรมสามารถหยุดการพยายามเชื่อมต่อซ้ำๆ และเปิดโหมด AP เพื่อให้ผู้ใช้เข้ามาตั้งค่ารหัสผ่านใหม่ได้ทันที
```
